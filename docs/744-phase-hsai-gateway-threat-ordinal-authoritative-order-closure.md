## Producer And Shell Rules

Every network, extraction, build, backend, and checker producer is one
top-level command with separate bounded stdout/stderr and a numeric status.
No shared producer block, shell helper function, pipeline acceptance, command
substitution acceptance, status reconstruction, or post-failure checkpoint is
allowed. Assertions run in the next top-level command and must finish before a
later producer. Where a parser is declared the sole acceptance command, it
contains no display, hash, checkpoint, cleanup, or later-stage operation.

This directly follows Bash's documented rule that a command list returns the
status of its last command; a later successful checkpoint must not replace a
failed validator status:
[Bash exit status](https://www.gnu.org/software/bash/manual/html_node/Exit-Status.html),
[Bash conditional constructs](https://www.gnu.org/software/bash/manual/html_node/Conditional-Constructs.html),
and [Bourne shell `exit`](https://www.gnu.org/software/bash/manual/html_node/Bourne-Shell-Builtins.html).
