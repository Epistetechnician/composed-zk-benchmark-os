## Main paper claims

The paper reports that opaque reasoning blocks returned by tested proprietary
LLM APIs were replayable across some sessions, users, and model versions within
provider ecosystems. It then reports a weaker compatible model being used as a
decoder for a stronger model's opaque block. This is a paper-reported security
observation about tested API behavior, not a repository observation or a proof
of any provider's internal cryptographic design. [Abstract and §§2.1–2.4](https://arxiv.org/pdf/2608.09867)

The four reported attack classes are:

1. extraction of proprietary reasoning for distillation;
2. extraction of private information from shared traces;
3. disclosure of hazardous information hidden from the visible answer; and
4. hidden prompt injection through an opaque block that is later replayed.

These are summarized in the abstract and developed in §§3–4 of the [paper](https://arxiv.org/pdf/2608.09867).
The public-trace scan is recorded here only at aggregate level: 315,320
reasoning blocks, 367 PII artifacts, and 182 credentials as reported by the
authors. No recovered item is copied or retained.

## Threat model

The paper models an unprivileged API adversary with no provider-infrastructure
access, server-side state visibility, or proprietary model weights. It separates
first-party attacks, where the attacker creates target traces, from
third-party attacks, where the attacker obtains another user's trace or causes
a victim to replay an adversarial trace. Both profiles require access to a
compatible decoder model in the provider ecosystem. [§2.1](https://arxiv.org/pdf/2608.09867)

## Experimental setup

The evaluations used provider APIs for Anthropic, OpenAI, and Google, with
controlled tasks drawn from AIME 2025, Codeforces/Open-R1, and Humanity's Last
Exam. The basic procedure collected an opaque block and replayed it through a
provider-specific decoder pipeline. The paper compared extracted-token counts
with API-reported thinking-token counts over 120 Codeforces problems, treating
the count relationship as a fidelity proxy. [§§2.4–2.5](https://arxiv.org/pdf/2608.09867)

## Attack vectors and observations

| Vector | Paper-level observation | Evidence ceiling |
| --- | --- | --- |
| Cross-model extraction | A compatible weaker model was reported to transcribe opaque content from a stronger model's block. | Tested API behavior under the reported model/version matrix; not universal provider compatibility. |
| Distillation | The attack can expose proprietary reasoning content to a party with API access. | Extraction-risk demonstration; not a measurement of student-model learning or faithful distillation. |
| Secret and PII extraction | Publicly shared opaque blocks can contain information unavailable in visible logs. | Aggregate privacy-risk demonstration; not an exhaustive prevalence estimate. |
| Hazardous hidden information | Hidden content can be exposed even when visible output refuses or is safe. | Security observation about hidden-channel exposure; not a mechanistic account of model reasoning. |
| Hidden prompt injection | An opaque block can carry an instruction that affects a later continuation. | Behavioral influence demonstration in the tested workflow; not proof of general prompt-injection transfer. |

The classifications above are bounded by the paper's own [§§3–4](https://arxiv.org/pdf/2608.09867)
and do not import its attack traces into this repository.

## Limitations

The paper limits its evaluation to specific model/API versions available during
early July 2026; provider cryptographic implementations are proprietary and
may change. It states that stochastic decoder output and the absence of
plaintext ground truth prevent complete token-level verification. Its public
trace scan is targeted rather than exhaustive. [§5.1](https://arxiv.org/pdf/2608.09867)

The paper's token-count agreement is therefore a proxy for extraction fidelity,
not plaintext ground truth and not proof of faithful computation. This boundary
is binding for the synthesis and for any future benchmark mapping.

## Mitigations proposed by the paper

The paper proposes stateful server-side trace retention with client-visible
opaque identifiers, cryptographic context binding to user/conversation/model or
prompt history, cross-model isolation, anomaly and velocity detection, provider
side revocation, and removal of opaque reasoning fields from shared logs. These
are proposed mitigations, not verified properties of HSAI or of this repository.
[§§5.4–5.5](https://arxiv.org/pdf/2608.09867)

## Disclosure, ethics, and reproducibility

The authors report disclosure to affected major model API providers, Microsoft,
and Hugging Face. They report that providers acknowledged receipt and that the
same attacks could no longer be launched after mitigations. They also report
isolated handling and deletion of recovered sensitive items. [§§5.2–5.4](https://arxiv.org/pdf/2608.09867)

The paper states that, as of August 2026, the Figure 1 attack was no longer
reproducible through the described API procedures because of provider
mitigations, and that the API experiments cost approximately $30,000 in API
credits. This makes the paper a frozen security prior work record, not a
currently reproducible provider test in this repository. [Reproducibility Statement](https://arxiv.org/pdf/2608.09867)

## Source-freeze nonclaims

- The paper does not establish the providers' exact cryptographic algorithms,
  keys, or envelope schemas.
- The paper does not establish that every recovered token is the target model's
  faithful private reasoning.
- The paper does not establish a general prevalence rate for exposed secrets.
- The paper does not establish mechanistic explanations, model introspection,
  consciousness, or causal telemetry access.
- This record does not authorize provider API probing, model execution, trace
  reuse, credential use, or artifact import.
