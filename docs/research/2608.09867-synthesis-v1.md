## Executive disposition

The paper is relevant security prior work. It reports that opaque provider
artifacts can be replayed and can expose hidden content or influence later model
behavior under tested API conditions. It does not prove plaintext faithfulness,
provider cryptographic internals, mechanistic explanations, privileged residual
telemetry access, HSAI security, or any Astral claim.

Disposition:

- Astral: supports the information/report distinction as an adjacent threat
  observation; it supplies no new Astral scientific evidence.
- HSAI: reinforces context binding, replay/freshness checks, revocation,
  quarantine, redaction, and non-authority rules.
- Benchmark OS: defines a candidate synthetic adversarial family named
  `OpaqueTraceReplay`.
- Repository ceiling: unchanged.
- V25: unchanged at `LocalDevelopmentPrivilegedTelemetryInformationPresence`.
- Stage 0C: blocked.
- Stage 1: blocked.
- Accepted Evidence Ledger mutation: not authorized.

The paper source for these conclusions is the [frozen paper record](2608.09867-source-freeze-v1.md);

## Astral crosswalk

The two pipelines are related but not interchangeable:

```text
paper:  opaque trace -> replay -> decoder -> extracted text or injection

Astral: actor -> controlled intervention -> residual telemetry
              -> external probe versus model report
              -> causal-effect validation
```

| Dimension | Paper establishes | Astral implication | Ceiling |
| --- | --- | --- | --- |
| Information presence | Hidden content can exist behind a visible summary or answer and may be recoverable through a compatible artifact path. | Supports treating visible reports as incomplete observables. | No residual-stream information-presence result. |
| Report faithfulness | Decoder text can track API token counts. | Supports separating report comparison from raw text recovery. | No faithful semantic ground truth. |
| Causal influence | Replayed hidden content can affect later output or action in tested workflows. | Security-side behavioral effect is relevant to control design. | No held-out intervention-effect prediction. |
| Privileged access | Attacker uses an opaque provider artifact and a compatible model. | This is an external artifact channel, not privileged telemetry. | No privileged residual access or self-report comparison. |

The paper does not test the Astral endpoint of directly measured held-out
intervention effects. It does not validate a mechanistic explanation and does
not unblock Stage 0C or Stage 1. V25 remains a single-checkpoint local result
with ceiling `LocalDevelopmentPrivilegedTelemetryInformationPresence`; no V25
concepts, assessment rows, configurations, or artifacts are reused. [V25
protocol](astral-self-modeling/46-telemetry-information-presence-v25.md)

## HSAI security and admission boundary

The paper's replay failure mode maps to this HSAI boundary:

```text
opaque provider artifact
-> strict typed candidate
-> user/session/model/context binding
-> predecessor or Merkle-root binding
-> nonce, freshness, replay, and revocation checks
-> accept, quarantine, or reject
-> append-only audit record
-> separately authorized state transition
```

| Control | Required treatment | Evidence status |
| --- | --- | --- |
| User/session binding | Candidate must carry stable context identifiers or digests; mismatch is reject/quarantine. | HSAI control requirement; not paper evidence. |
| Model/version binding | Candidate must bind the expected model/version; wrong-model replay is rejected. | Paper threat-model input; HSAI implementation evidence would be separate. |
| Predecessor/Merkle-root binding | Candidate must bind the expected prior block or journal root. | HSAI design control; not claimed by the paper as verified. |
| Nonce and replay prevention | Enforce freshness, uniqueness, ordering, and duplicate rejection. | Paper motivates the control; no HSAI runtime result here. |
| Revocation | Revoked or stale artifacts remain quarantined and cannot authorize state. | Paper proposes provider-side revocation; HSAI status remains untested. |
| Raw-trace nonretention | Keep only typed metadata, digests, labels, and redaction results. | Required repository hygiene; no raw paper trace imported. |
| Secret/PII redaction | Synthetic tests use sentinels only; real secrets and PII are never fixtures. | Design and review requirement. |
| Explicit nonclaims | Every accepted candidate carries a bounded claim ceiling. | Existing HSAI admission rule. |
| No authority from text/output | Provider text, model output, or decoder output may propose but never directly mutate governed state. | Existing [admission boundary](../134-pcsm-governed-agent-admission-boundary-spec.md). |

The paper's mitigation discussion supports contextual binding, cross-model
isolation, revocation, and log hygiene as threat-model controls. It does not
demonstrate that HSAI is secure. The repository rule remains: untrusted output
becomes a strict candidate, passes deterministic admission, and only then may a
separately authorized state transition occur. [HSAI admission specification](../134-pcsm-governed-agent-admission-boundary-spec.md)

## Benchmark OS adapter design: `OpaqueTraceReplay`

This is a synthetic adapter contract. The typed pure-data surface is implemented
locally; it is not a provider integration, benchmark result, or
production-readiness claim.

The follow-up [scientific admission validation](61-opaque-trace-replay-scientific-admission-validation-v1.md)
executes the ten synthetic variants through an independent local admission
evaluator. It compares typed fail-closed admission against a raw-output
passthrough control. This validates the local control hypothesis only; it does
not execute a provider/model attack or produce a benchmark score.

### Semantic case contract

Each case should contain:

```text
family_id = OpaqueTraceReplay
variant_id
source_case_digest
expected_verdict              # semantic oracle owned by benchmark OS
mutation_provenance
public_private_boundary
adapter_result
quarantine_status
claim_ceiling
```

The semantic oracle owns `expected_verdict`. The API or adapter owns only the
observation of acceptance, rejection, malformed input, or quarantine. This
preserves the repository's candidate -> validation -> evidence separation and
the HSAI rule that provider output has no direct authority. [HSAI admission
boundary](../134-pcsm-governed-agent-admission-boundary-spec.md)

### Variant matrix

| Variant | Synthetic mutation | Expected semantic verdict | Required result treatment | Ceiling |
| --- | --- | --- | --- | --- |
| `valid_same_session` | Correct user, session, model, predecessor, nonce, and order. | Accept candidate; no authority granted automatically. | Record accepted observation and audit digest. | Local adapter contract only. |
| `wrong_user_replay` | Change user binding while retaining artifact bytes. | Reject or quarantine. | Record binding mismatch; no state mutation. | Local negative-control evidence. |
| `wrong_session_replay` | Change session binding. | Reject or quarantine. | Record session mismatch and quarantine. | Local negative-control evidence. |
| `wrong_model_replay` | Change model/version binding. | Reject or quarantine. | Record model mismatch; no decoder authority. | Local negative-control evidence. |
| `out_of_order_block` | Swap predecessor/order metadata. | Reject. | Record ordering or predecessor failure. | Local negative-control evidence. |
| `duplicate_block` | Replay an already consumed nonce/digest. | Reject. | Record duplicate detection. | Local negative-control evidence. |
| `stale_or_revoked_block` | Expire or revoke an otherwise valid candidate. | Reject or quarantine. | Record freshness/revocation status. | Local negative-control evidence. |
| `hidden_injection` | Add a non-secret synthetic injection marker inside the opaque payload. | Reject, quarantine, or safe no-op according to the frozen oracle; never execute payload. | Record payload-risk classification separately from adapter acceptance. | Security mutation observation only. |
| `secret_bearing_transcript` | Use a named synthetic secret sentinel, never a real secret. | Reject or quarantine and redact. | Record redaction result without retaining sentinel content. | Privacy-hygiene regression only. |
| `malformed_envelope` | Break required type, digest, nonce, or encoding field. | Reject. | Record deterministic parse/validation error. | Contract regression only. |

No variant requires a live provider API, real credential, PII, opaque signature,
or production trace. The adapter must report separate axes for semantic verdict,
binding validation, quarantine behavior, provenance completeness, and claim
ceiling. It must not convert API acceptance into proof of cryptographic
correctness or security.

## Future experiment register

These are design candidates only. Each requires a new protocol identity, named

authorization before execution.

### Candidate A: artifact-only versus telemetry

Compare a text-only observer, opaque-artifact metadata observer,
activation-telemetry observer, shuffled-artifact control, and
shuffled-telemetry control. The endpoint is directly measured held-out
intervention effects, not recovered reasoning text. The design must use fresh
actors, concepts, assessment rows, and artifacts disjoint from V25 and must not
alter V25's frozen configuration. The docs-only protocol is now recorded in
[V26 causal-channel separation](astral-self-modeling/48-causal-channel-separation-v26.md)
and its [authorization record](astral-self-modeling/49-v26-authorization-record.md).

Ceiling: at most a new local intervention-effect comparison for the authorized
protocol. It cannot establish faithful explanation, global introspection,
consciousness, Stage 0C, Stage 1, or production monitoring.

### Candidate B: context-binding intervention

Use a local synthetic envelope system to test whether an observer or agent
distinguishes valid context, wrong session, wrong model, reordered block,
replayed block, and injected instruction. This is a security/control experiment,
not an introspection experiment. It must use non-secret sentinels and a typed
semantic oracle.

Ceiling: local context-binding and fail-closed behavioral evidence only; no
provider cryptographic or HSAI security claim.

### Candidate C: admission-impact test

Use synthetic provider/model outputs to compare an intentionally removed
admission check with the typed admission path. Measure whether an unauthorized
state transition is possible in the unsafe control and prevented by the
fail-closed path. Keep the experiment in HSAI governance; do not present it as
Astral confirmation or provider evidence. [HSAI admission specification](../134-pcsm-governed-agent-admission-boundary-spec.md)

Ceiling: local admission-kernel regression evidence; no full-security,
production-readiness, or external-provider claim.

### Paper-informed Astral result: narrative versus mechanism

The paper's distinction between recovered reasoning text and faithful
computation was converted into a separate local V30 protocol. A planted actor
was evaluated with a plausible narrative object, a measured mechanism object,
and a shuffled mechanism control against directly computed held-out intervention
effects. The mechanism-only observer achieved MSE `0.0`, versus `0.5` for the
narrative-only observer and `12.0` for the shuffled mechanism. This is local
measurement-validity evidence for keeping narrative, mechanism, and
verification as separate objects; it is not evidence from a trained model or a
provider attack. See the [V30 protocol](astral-self-modeling/62-narrative-mechanism-verification-v30.md)
and [execution record](63-v30-execution-record-2026-08-14.md).

Ceiling: `LocalDevelopmentPlantedMechanismVerification`. No V25 claim,
Stage 0C, Stage 1, mechanistic-faithfulness, general-introspection, HSAI
security, or provider-cryptography claim is raised.

The follow-up [V31 stress test](astral-self-modeling/64-narrative-mechanism-stress-test-v31.md)
expanded this into 36 deterministic tasks with zero, fit-mean, narrative, and
shuffle baselines. The measured mechanism beat every baseline on all 24
clean/noisy linear tasks; 7 of 12 unmodeled-interaction tasks failed and were
retained as an explicit model-class limitation. This strengthens the local
measurement-validity case while demonstrating that the instrument must expose
failure modes rather than hide them.

V31 ceiling: `LocalDevelopmentSyntheticMeasurementStressTest`. It does not
raise the Astral, HSAI, benchmark, or provider claim ceilings.

The [V32 scoring-layer contract](astral-self-modeling/66-astral-scoring-layer-contract-v32.md)
now routes evidence through behavior, mechanism, and introspection layers with
explicit prerequisites. Its six-profile regression produced zero unsupported
upward promotions and classifies V30/V31 as mechanism evidence only. This is a
claim-governance result, not new model evidence.

The subsequent [V33 readiness audit](astral-self-modeling/68-model-family-replication-readiness-v33.md)
found no fresh per-layer actor. The existing Qwen3.5 public-ABI path is
ready only for its previously scoped final-embedding feasibility protocol, not
for a new mechanism replication. Execution therefore stops at custody and
instrument readiness.

The follow-up [V34 custody handoff](69-fresh-actor-custody-handoff-v34.md)
turns that stop condition into a local fail-closed metadata preflight. It binds
fresh actor, source, runtime, launcher, split, validator, and artifact-root
digests; rejects reserved actors and forbidden raw material; denies unknown
trace or credential fields; and requires the assessment to remain closed. V34
validates only the contract. It does not create custody, authenticate any
artifact, authorize model execution, or change the Astral claim ceiling.

The [V35 custody packet](71-fresh-actor-custody-packet-v35.md) adds deterministic
compact serialization, a recomputable packet digest, schema-version binding,
nonce uniqueness, and predecessor ordering. These are local transport and
replay-preflight controls only. They do not authenticate the underlying actor
or artifacts, provide provider cryptographic evidence, authorize model
execution, or change the Astral claim ceiling.

The [V36 replay manifest](73-fresh-actor-custody-replay-manifest-v36.md) adds a
serializable append-only accepted chain and typed quarantine records that do
not retain rejected packet payloads. This strengthens local replay hygiene only;
it is not durable distributed replay prevention, attestation, provider
security evidence, or execution authorization.

The [V37 execution-eligibility gate](75-astral-execution-eligibility-gate-v37.md)
composes the custody manifest with declared instrument readiness, independent
review, nonclaim acknowledgement, a `Level0DesignNote` ceiling, and disabled
external execution. Its positive result is only eligibility for a separate
human authorization step; it is not model execution, scientific evidence, or
security proof.
