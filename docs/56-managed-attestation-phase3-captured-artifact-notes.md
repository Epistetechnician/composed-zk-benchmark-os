# Managed Attestation Phase 3 Captured Artifact Notes

This add-on integrates the useful `perth` conductor worktree content without
replacing the existing fixture-oriented `PhalaAttestationVerifier` seam.

## What Shipped

- `PhalaArtifactBundle`
- `PhalaValidationPolicy`
- `ValidatedPhalaAttestation`
- `PhalaValidationError`
- `parse_phala_artifact`
- `validate_phala_artifact`
- `PhalaArtifactAttestationLane`
- Public fixture:
  `crates/hsai-attestation-phala/tests/fixtures/phala_trust_center_app_2026_06_16.json`

The fixture is a captured Phala/dstack Trust Center artifact observed at
`2026-06-16T14:20:17Z`. It includes raw quote hex, report data, compose JSON,
compose hash, RTMR values, an RTMR3 event log, Docker image digests, app metadata,
and managed verifier metadata.

## Local Checks

`validate_phala_artifact` checks:

- expected anchor id;
- managed verifier metadata for the captured Trust Center mode;
- freshness under a local max-age policy;
- report-data equality and quote-contained report data;
- nonce and case-hash prefix binding inside report data;
- compose JSON SHA-256 against the captured compose hash;
- app id, instance id, compose hash, and OS image hash event payloads;
- RTMR3 replay over the ordered event-log digests;
- required Docker image digest presence.

`PhalaArtifactAttestationLane` emits an `Attested` anchor-validity envelope only.
It never emits `Proven`.

## Claim Boundary

This is managed-verifier captured-artifact validation. It is not local Intel DCAP
quote verification, not managed-service signature or JWKS/JWT verification, not
external attestation evidence produced by this repository, not benchmark evidence,
and not proof.

The public fixture was not generated by this repository with a fresh HSAI-owned
challenge protocol. The validator checks the captured `report_data` exactly and
checks the nonce/case-hash prefix carried by the fixture, but this does not by
itself authorize Phase 4 anchor-registry claims.

Phase 4 still requires a future captured artifact that is explicitly generated
from the HSAI challenge binding for `agent_pubkey || nonce || case_hash`, or a
deliberate spec update lowering that claim.
